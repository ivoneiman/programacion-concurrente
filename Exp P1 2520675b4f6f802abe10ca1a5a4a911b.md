### 📘 Resumen Explicativo – Práctica 1: **Variables Compartidas**

Esta primera práctica introduce los conceptos básicos de **programación concurrente con variables compartidas**, mostrando los problemas que aparecen cuando varios procesos acceden y modifican datos al mismo tiempo.

---

### 1. **Ejercicio inicial**

Acciones atómicas: Mientras se ejecuta una acción, ningún proceso puede intervenir y no podrán tocar variables ni producir interferencias.

- Se plantea un programa con una variable compartida `x` y dos procesos (A y B) que la modifican sumando distintos valores.
- Se descompone cada instrucción en operaciones atómicas de grano fino **(load, add, store).**
- Según el intercalado de instrucciones, `x` puede terminar en diferentes valores (4, 6 o 9).
    - Historias:
        - 1-2-3-4-5-6 = 9
        - 4-5-6-1-2-3 = 9
        - 1-2-**4**-5-3-6 = ~~6~~ , 4
        - 1-4-2-5-3-6 = ~~6~~ , 4
        - 1-4-2-5-6-3 = ~~4~~ , 6
    
    👉 Conclusión: el resultado depende del **interleaving** y se generan condiciones de carrera.
    

---

## Soluciones de grano grueso

### 2. Sentencias **Await y Exclusión Mutua**

- Para resolver interferencias se introducen las **sentencias `await`**:
    - `<await (B); sentencias>` → el proceso espera a que la condición `B` sea verdadera y ejecuta en forma atómica la sección crítica.
- Se logra:
    - **Exclusión mutua**: un solo proceso accede a la Sección Crítica a la vez.
    - **Sincronización por condición**: procesos se coordinan mediante una variable compartida.

---

### 3. **Ejemplo 2 – Contador de entradas a un salón**

- Varias puertas cuentan los alumnos que entran y además se lleva un total.
- Problema: `Total = Total + 1` no es atómico → puede dar un total menor a la suma de parciales.
- Solución: proteger solo la operación sobre la variable compartida, mantener los contadores parciales locales (no necesitan exclusión).

---

### 4. **Ejemplo 3 – Docente y alumnos en un examen**

“Sincronizar tanto al iniciar el examen como al terminarlo. Si no, significaría que el docente estaría atendiendo a una persona que ya se fué”

- Un docente toma examen oral a 30 alumnos en orden.
- Se usa una variable compartida `Actual` para indicar el turno.
- Los alumnos hacen `await (Actual == id)`.
- Se agrega sincronización con una variable `Listo` para indicar que terminó el examen.
- Se ve la necesidad de **resetear y coordinar** condiciones entre docente y alumnos para evitar errores.

```rust
int Actual = -1;
bool Listo = False;
Ok = false;
Process Alumno [id: 0..29]
{ <await (Actual == id)>;
	Ok = true;
  //Rinde examen
  <await Listo; Listo = false>//Espera a que termine el examen 
  // No es necesario que la asignación esté dentro de la SC.
}

Process Docente
{ for i = 0..29
  { 
    Actual = i // Llama al alumno i
    <await(Ok)>; // Espera a que llegue el alumno
    Ok = false;
    // Toma al examen
    <Listo = true>;// Avisa a i que terminó (igual no hay int en este momento)
    <await (not Listo)> // Acá si podría haber interferencia
	}
}
```

### 5. **Ejemplo 4 – Cajero automático con prioridad**

- Varias personas llegan a un cajero único.
- Deben esperar en cola; si es una persona anciana, se ubica al frente.
- Se modela con una estructura `colaEspecial` y variables `Siguiente`.
- Los procesos deben: (Verificar si el cajero está ocupado PRIMERO para ver si puedo pasar)
    1. Encolarse.
    2. Esperar su turno con `await (Siguiente == id)`.
    3. Usar el cajero.
    4. Liberarlo y pasar el turno al siguiente (o marcarlo libre con `1`).
        
        👉 Ejemplo clásico de **cola con prioridad y exclusión mutua**.

### ✅ Ideas clave de esta práctica

1. **Problema de las variables compartidas**: producen condiciones de carrera si no se protegen.
2. **Sección crítica**: debe ser atómica, protegida mediante sincronización.
3. **Await**: permite tanto exclusión mutua como sincronización por condición.
4. **Diseño eficiente**: usar variables locales siempre que sea posible; proteger solo lo estrictamente necesario.
5. **Ejemplos progresivos**:
    - Contadores en paralelo.
    - Docente–alumnos (sincronización ordenada).
    - Cajero con prioridad (cola compartida y turnos).

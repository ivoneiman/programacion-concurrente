### Comunicación

Envío (send): la operación no es bloqueante, deposita el mensaje al final del canal y continua su ejecución

- `send nombrecanal (mensaje)`
- `send nombrearreglo[i] (mensaje)`

Recepción (receive): la operación es bloqueante, si el canal está vacío se demora hasta que haya al menos un mensaje en él, luego saca el primer mensaje del canal (el más viejo FIFO)

- `receive nombrecanal (Variables para el mensaje)`
- `receive nombrearreglo[i](Variables para el mensaje)`

Consultas por mensajes pendientes (empty): esta función retora un booleano que indica si el canal está vacío o no. Usar con cuidado cuando el canal tiene más de UN posible receptor

- `empty (nombrecanal)`
- `empty (nombrearreglo[i])`

Uso de Sentencias de Alternativa Múltiple (**IF no determinístico**) y Alternativa Iterativa Múltiple (**DO no determinístico**). Puede generar busy waiting que en PMA está permitido (igual hay que tratar de evitarlo):

Debemos considerar que no puede haber más de un receptor preguntando por el empty, porque genera demora innecesaria. Entonces, debemos crear un *Coordinador* quien recibe los reportes envíados, y quien interactúa con los Empleados para que le pidan a ese proceso un reporte a resolver. Para las Personas estos cambios son “invisibles”, por lo que no se modifican

```cpp
chan Reportes(texto);
chan Pedido(int); //empleado le pide reporte 
chan Siguiente[3](texto);

Process Persona[id:0..N-1]{
	text R;
	while (true){
		R = generarReporteConProblema;
		send Reportes (R)
	}
}

//Si o si le tiene que contestar al Empleado 
Process Coordinador{
	texto Rep;
	int **idE**;
	while (true){
		receive Pedido(**idE**);
		if (empty(Reportes)){
			Rep = "VACIO"
		}
		else {
			receive Reportes(Rep);
		}
		send Siguiente[**idE**](Rep);
	}
}

//Debe esperar si o si la respuesta del Coordinador porque si no se genera un desfase de atención
Process Empleado[id:0..2]{
	texto Rep;
	while (true){
		send(Pedido(**id**));
		receive Siguente[id](Rep);
		if (Rep <> "VACIO") {
			resolver(Rep);
		}
		else delay(600); //lee 10 min
	}
}
```

### Comunicación Guardada

Permite seleccionar de forma no determinística entre varias alternativas de comunicación (en el caso de la práctoca SÓLO RECEPCIONES) en base a las condiciones del proceso y los mensajes que están listos para ser recibidos.

If

Estructura con dos alternativas al menos, que tendrán una guarda.

- Guardas: cada alternativa es una guarda con la forma: B; C→S
    - B: condición booleana que puede no estar (en ese caso se considera true), e indica si el proceso está o no en condiciones de procesar el mesaje recibido en C.
    - C: sentencia de comunicación (práctica sólo RECEPCIÓN) que seguro debe estar.
    - S: conjunto de sentencias que se ejecutarán en caso de ser elegida la guarda.

***Evaluación de una guarda:***

- **Éxito:** la condición **booleana es true (o no la tiene)** ***y*** la comunicación se puede realizar sin producir demora (**el emisor está esperando para hacer la comunicación**).
- **Fallo:** la condición booleana es Falsa, sin importar lo que ocurra con la sentencia de comunicación.
- **Bloqueo:** la condición booleana es Verdadera (o no la tiene) pero la comunicación NO se puede realizar sin producir demora (el emisor aún no llegó a la sentencia de envío). ****

> **Como ambas guardas deben formarse con una sentencia de recepción, en la segunda, debe esperar a que LE PIDAN el siguiente carácter, y recién ahí se lo puede envíar (para evitar hacer el envío cuando el receptor no está listo para hacer la comunicación)**
> 

```cpp

Process Oeste{
	while (true) Copiar!(generar caractér);
}

Process Copiar{
	char buffer[80]; int front=0, rear=0,cantidad=0;
	do cantidad < 80; Oeste?(buffer[rear]) -> 
																					cantidad = cantidad + 1;
																					rear = (rear + 1) MOD 80;
		 cantidad > 0; Este?() -> 
													 Este!(buffer[front])
													 cantidad = cantidad - 1;
													 front = (front + 1) MOD 80;
}

Process Este{
	char c;
	while true{
		Copiar!(); //Le pide un caracter
		Copiar?(c);//Lo recibe
		//usa c
	}
}

```

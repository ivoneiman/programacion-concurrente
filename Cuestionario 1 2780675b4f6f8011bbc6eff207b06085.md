1. Puedo nombrar modelos de concurrencia como para memoria compartida, procesos/hilos que acceden a variables comunes. También podemos hablar de pasajes de mensajes. Pero así como ejemplos, puedo nombrar los siguientes:
    - **Sistemas operativos:** planificación de procesos, manejo de memoria, drivers de dispositivos.
    - **Aplicaciones interactivas:** videojuegos, GUI con múltiples eventos.
    - **Sistemas distribuidos:** servidores de bases de datos, aplicaciones web, computación en la nube.
    - **Aplicaciones científicas:** simulaciones, cálculos masivos en clusters.
2. La concurrencia se describe de mejor manera, como múltiples procesos funcionando concurrentemente para exprimir el uso de la CPU al máximo. Entonces podemos decir que, permite modelar sistemas del mundo real, donde **múltiples actividades ocurren simultáneamente**.
3. El deadlock se produce cuando varios procesos se bloquean, donde cada uno de ellos, espera un recurso del otro, que no puede liberar por dependencia. Entonces se genera una especie de cadena, donde se encuentran bloqueados todos los procesos: consecutivamente no pueden liberar sus recursos, debido a que necesitan los de otro para continuar, y así ocurre con cada uno de ellos.
4. La inanición se produce cuando un proceso no puede acceder a un recurso, ya que siempre que quiere acceder, otro proceso le gana de mano el derecho para acceder a aquél.
5. El no determinismo se refiere a la intercalación de instrucciones entre procesos e hilos que se ejecutan en paralelo, la cual es decidida por el SO de formas diferentes en cada ejecución. Esto significa que el orden relativo en el que se ejecutan las instrucciones de distintos procesos no está garantizado. Entonces dos ejecuciones del mismo programa concurrente, pueden dar resultados distintos.
    1. Importa porque el no determinismo concurrente, obliga a usar mecanismos de sincronización como semáforos, monitores, etc., para garantizar exclusión mutua y orden.
    2. Si no se controla el no determinismo, aparecen condiciones de carrera, deadlocks o resultados incorrectos.
6. La comunicación es la forma en que se transmiten los datos entre tareas concurrentes. Existen dos mecanismos de comunicación:
    - **Memoria compartida**: Intercambian información sobre la memoria compartida. Lógicamente no pueden operar simultáneamente sobre la memoria compartida, lo que obliga a **bloquear y liberar** el acceso a la memoria. (Variable control tipo semáforo que habilite o no el acceso)
    - **Pasaje de mensajes:** Es necesario establecer un **canal** lógico o físico para transmitir la información entre procesos. También el lenguaje debe proveer un protocolo adecuado. Para que la comunicación sea efectiva los procesos deben “saber” cuándo tienen mensajes para leer y cuándo deben transmitirlos.
7. Sincronización es la posesión de información acerca de otro proceso para coordinar actividades. Para ello se usan:
    - **Exclusión mutua:** Asegurar que un único proceso a la vez está accediendo a un recurso compartido en un instante de tiempo. Si el programa tiene **secciones críticas** que pueden compartir más de un proceso, la exclusión mutua evita que dos o más procesos se encuentren en la misma sección critica al mismo tiempo
    - **Por condición:** Permite bloquear la ejecución de un proceso hasta que se cumpla una condición dada
    - Semáforos
    - Monitores
    - Barreras
    
    b. Como poder pueden. Ejemplos:
    
    - **Productor/Consumidor con buffer acotado**
        - Usa un semáforo binario para **exclusión mutua** al acceder al buffer.
        - Usa dos semáforos contadores (`llenos` y `vacíos`) para **sincronizar la disponibilidad** de ítems/espacios.
    - **Sistema de impresión compartida**
        - Usa un `await` o semáforo binario para garantizar que **solo una persona use la impresora a la vez**.
        - Usa una **cola (FIFO)** para sincronizar el **orden de llegada**.
8. La interferencia se refiere a el acceso en paralelo a una Sección Crítica, de dos o más procesos, que interfieren con los datos que se manejan dentro de ella, y produce un desface en la integridad de ellos.
9. La propiedad **ASV (At Most Once)** establece que **una sentencia en un programa concurrente debe ejecutarse, como máximo, una vez por cada proceso que la alcanza**, independientemente de la intercalación de los procesos.
